## 為什麼這次 refactor

原本的 Step 5（2026-09-05）有三個問題：

1. **命名不對齊 Passcreator API**：`notificationRadius` 是後端自創命名，Passcreator UI 跟 PKPass spec 都叫 `locationsMaxDistance`。新使用者讀後端 schema 會困惑。
2. **lat/lng 變 optional 是錯的**：原本「允許空 row」讓使用者可以加 row 但不填 lat/lng 就離開 step。Apple Wallet 在 generation time 不會 complain，但使用者最後看到「鎖屏沒反應」會以為是 bug。
3. **沒有 toggle 控制 Step 5 是否要填**：原本 Step 5 永遠 skippable，但有些客戶（比如純電子票券）根本不要 location trigger，UI 應該給「完全跳過」的選項。

## 變更範圍

| 變更 | 從 | 到 |
|---|---|---|
| 距離欄位命名 | `notificationRadius` | `locationsMaxDistance`（Passcreator 對齊）|
| `relevantText` | 無 | 加回 per-row, optional string ≤ 100 字（Apple Wallet `relevantLocations[].relevantText`）|
| `latitude` / `longitude` | optional（可空 row）| **必填**（zod schema 拒絕 row 沒 lat/lng）|
| `locationsDisabled` | 無（Step 5 永遠可跳過）| 加 checkbox toggle，決定 Step 5 是否必填 |
| `skipNotice` 文案 | 「本步所有欄位皆非必填」 | 「目前已停用地理位置推播，Step 5 已收合」 |

## 設計決策

| 決策 | 選擇 | 理由 |
|---|---|---|
| `altitude` 欄位 | **不加** | spec 沒要求，加了會跟 Passcreator UI 預設 shape drift |
| 舊 `notificationRadius` 資料 | **寫 migration 重命名** | DB 內部一致性，前端 loadSettings 只需讀新欄位 |
| `locationsDisabled=true` 時資料處理 | **清空 locations + locationsMaxDistance** | DB 保持乾淨，避免 stale data（`setLocationsDisabled(true)` setter 在切到 disabled 時同步清空 store 跟 payload） |
| `locationsMaxDistance` 範圍 | 沿用 [100, 1000] 公尺 | PassKit spec 不變 |
| `relevantText` 長度上限 | 100 字 | Passcreator UI 預設；鎖屏可閱讀長度 |
| `initialMessage` 顯示 | `locationsDisabled=true` 時整個 Step 5 收合 | 推播通知也是 location-triggered，語意一致 |

## Step 5 開關 UX 行為

```
[✓] 啟用地理位置推播          ← locationsDisabled toggle (預設勾選 = false)
  ├─ 勾選時展開：
  │   ├─ 推播訊息 input
  │   ├─ 推播範圍半徑 input（100 ~ 1000 公尺）
  │   └─ 地點 list（≥ 1, 每列 name + lat + lng + relevantText）
  └─ 取消勾選時：
      ├─ 清空 locations + locationsMaxDistance
      └─ Step 5 Next 按鈕永遠可用
```

`isStep5Valid()` 邏輯：
- `locationsDisabled === true` → valid（Next 可按）
- `locationsDisabled === false` → 必滿足：locations.length ≥ 1 + 每列 name+lat+lng 都有值 + `locationsMaxDistance` 不為 null 且在 [100, 1000]

## LocationsField 空狀態 hint 改為紅框

```diff
- {locations.length === 0 && (
-   <p className="rounded-md border border-dashed border-border bg-muted/40 ...">
-     {t('step5.locations.maxHint')}
-   </p>
- )}
+ {locations.length === 0 && (
+   <p className="rounded-md border border-dashed border-destructive bg-destructive/5 ...">
+     {t('step5.locations.locationsMinOneHint')}
+   </p>
+ )}
```

理由：當 `locationsDisabled=false` 且使用者還沒新增任何地點，workspace `isStep5Valid()` 已經 disable Next 按鈕。視覺上要明確提示「這是阻擋你繼續的錯誤」而不是「中性提示」。
