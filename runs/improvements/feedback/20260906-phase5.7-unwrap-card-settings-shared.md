## 根因分析

### 為什麼 inline copy-paste 是反 pattern

| ❌ inline copy-paste | ✅ shared extraction |
|----------------------|---------------------|
| drift 風險永遠存在 | single source of truth |
| vitest 必須各別 mock | 1 份單元測試 = 3 consumer 受惠 |
| RN migration 必須重寫 | RN consumer 直接 import 即可 |
| Bug fix 必須多檔 | Bug fix 1 處 = 3 consumer 受惠 |

業務邏輯（包含 defensive unwrap、validation、merge）必須在 `packages/shared/`，這是 SAOME `023-shared-package.mdc` 鐵律的子條款。

### 為什麼不是 `packages/shared/utils/` 而是 `packages/shared/logic/cardSettings.ts`

`packages/shared/logic/` 是 SAOME 業務邏輯純函式的固定位置（已有 `member` / `order` / `pass` / `auth` / `imageCrop` / `color` / `links`）。`unwrapCardSettings` 是 cards-specific business logic，符合這個資料夾的定義。

## 教訓

1. **業務邏輯（包括 defensive unwrap）必須在 `packages/shared/`** — backend + frontend + RN 共用
2. **Drift 是必然的**：一旦 logic 在 2 個地方都寫，會有一邊更新一邊沒更新。即使這次 trace 看起來同步，長期必然 drift
3. **Vitest alias order 是 prefix-match**：generic entry 必須放最後（最 specific 必須先宣告），否則 swallow 永遠 fail 解析
4. **`packages/shared/logic/` 是固定的 business logic 資料夾位置** — 對齊 `member` / `order` / `pass` / `auth` / `imageCrop` / `color` / `links` 的命名規則
5. **修法分兩批**：先 ship shared extraction 證明 consumer import 能 work（commit fa18ae9），未來再看是否要拔 `cardSettings.ts` 內聯（commit 後單元測試已 ship）
