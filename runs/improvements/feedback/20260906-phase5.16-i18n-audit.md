## 症狀

> 「`apps/frontend/scripts/verify-i18n-keys.mjs` 在 audit 17 個 i18n namespaces 的 cross-locale drift 時，遇到兩種 false-positive，導致 audit 失準」

### 三層問題

| 層 | 觀察 |
|----|------|
| **Drift 真實存在** | `auth.zh-TW.ts` 缺 7 keys, `landing.zh-TW.ts` 缺 2 keys, `legal.{zh-TW,en}.ts` 有 empty placeholder key |
| **Script 抓不到** | regex parser 對 `cardEditor.zh-TW.ts: "Failed to create card:"` 的 `card` identifier 視為 missing key，誤報 |
| **Script 抓得到但 silent** | 早期版本只 warn 不 fail |

---

## 根因分析

### 為什麼 regex parser 會誤判

```typescript
// 早期 audit script
const keyRegex = /i18nKey\.([a-zA-Z]+)/g;
```

會把翻譯值內的 identifier 當 key：

```typescript
// cardEditor.zh-TW.ts
export default {
  cardEditor: {
    backFieldsEmpty: 'Failed to create card:',   // ← "card" identifier 被誤判
  },
};
```

regex 無法分辨「`i18nKey.backFields` 是 key usage」vs「翻譯值內的 plain text」。

### Why matters

- 早期 audit 對 drift 抓不到 → 漏掉的 keys 永遠 drift
- 一旦真的 missing key 出現於 production UI → 顯示 raw key (e.g. `dashboard.header.subtitle`) → 使用者看到破碎字串
- 這跟 2026-09-05 `step4-i18n-counter` raw key 事故是同 pattern（`step4.backFields.counter` 兩個 locale 都漏）

### 為什麼 audit 只 warn 不 fail

早期是「audit script 用 console.warn 表示 drift」，沒整合進 CI gate → 人看就修、不看就累積。

## 修法 — 3 階段

### Stage 1 — 普查全部 17 namespaces

清單：

```
auth, landing, legal, passNotification, theme, nav, member,
dashboard, cardEditor, cardBuilder, passCard, passPreview,
logoUpload, payment, billingCycle, billingHistory, feeManage
```

逐 namespace 比對 zh-TW vs en，列出 missing / extra / diff keys。

### Stage 2 — 修 drift

| Namespace | locale | 缺漏 keys | 修法 |
|-----------|--------|-----------|------|
| `auth` | zh-TW | `login.accountEmailHint`, `login.passwordHint`, `login.confirmPasswordMismatch`, `login.error.{email,invalidCredentials,required,tooManyAttempts,unknown}` (6 nested error keys), `register.step1Title`, `register.step2Title` | 補完整 zh-TW 翻譯 |
| `auth` | en | `login.comingSoon`, `login.switchToRegister` | 加對稱 en 翻譯(之前只有 zh-TW 有) |
| `landing` | zh-TW | `footer.slogan`, `footer.features` | 補齊 footer 區塊 |
| `legal` | both | `terms.s1p3` 是 empty placeholder | 移除整個 key(consumer path 已斷) |
| 其餘 13 namespaces | both | 無 drift | clean |

總計：

- 7 keys 補進 `auth.zh-TW.ts`
- 2 keys 補進 `landing.zh-TW.ts`
- 2 keys 對稱補進 `auth.en.ts`
- 1 placeholder key 從 `legal.{zh-TW,en}.ts` 移除

### Stage 3 — Hardened `verify-i18n-keys.mjs`

#### 從 regex → string-aware parser + JSON round-trip

```js
// Before (regex, false-positive prone)
const keyRegex = /i18nKey\.([a-zA-Z]+)/g;

// After (string-aware + JSON round-trip)
function normalizeStrings(source) {
  // Walks single-quoted, double-quoted, template strings with proper escape handling
  // Then JSON.parse round-trips the result
  // Falls back to brace/quote walker if JSON.parse fails
}
```

`normalizeStrings` 處理：

| String type | 處理 |
|-------------|------|
| 單引號字串 | `'key': 'value'` |
| 雙引號字串 | `"key": "value"` |
| template literal | `` `key` `` |

JSON.parse round-trip 把字串內的 escape 序列（如 `\u`）標準化；如果 parse 失敗才 fall back 到 brace/quote walker。

#### 從 warn → hard-fail CI gate

```js
// Before
if (missingKeys.length > 0) {
  console.warn('Drift found, please fix');
  process.exit(0);   // 永遠通過
}

// After
if (missingKeys.length > 0) {
  console.error(`FAIL: ${missingKeys.length} i18n drift(s) found`);
  for (const ns of missingKeys) console.error(`  - ${ns.file}: ${ns.keys.join(', ')}`);
  process.exit(1);   // CI fail
}
```

整合進 `.github/workflows/deploy.yml`：

```yaml
i18n:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-node@v4
      with:
        node-version: '20'
        cache: 'npm'
        cache-dependency-path: 'package-lock.json'
    - run: npm ci
    - run: npm run verify:i18n --workspace=apps/frontend
```

#### 升級為 reporter：`cross-locale-drift-report.mjs`

新增 sibling script `apps/frontend/scripts/cross-locale-drift-report.mjs`：產生 markdown table report（給人類 review）+ JSON report（給其他 tool consume）。

## 教訓

1. **i18n drift 必須在 PR time 抓**：一旦 merge 到 production，UI 顯示 raw key，使用者體驗損毀
2. **Regex parser 對 TS source code 是天生不準**：string-aware + JSON round-trip 是正確解
3. **CI gate 必須 hard-fail**：audit script 只 warn 不 fail 等於沒有 gate
4. **Cross-locale 對稱性**：新 locale-only key（e.g. zh-TW 加 `login.comingSoon`）必須 backport 到對稱 locale（en）
5. **Empty placeholder key 也是 drift 的一種**：會被 consumer 當 truthy key 顯示空字串
6. **i18n audit 應該整合進 deploy.yml**：跟 typecheck / vitest / lint 同層，每次 PR 都驗
