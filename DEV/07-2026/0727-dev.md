### 教訓（給下次 session）

#### 1. 「完成」的定義必須包含驗證輸出

不能說「程式碼寫完了」。必須說「以下指令全 exit 0：
- `npm run typecheck`
- `npm run lint`
- `npm test` → N/N passed
- `npm run build` → dist/ 產出」

**預防**：commit message footer 必填「Verification: typecheck: exit 0; lint: exit 0; test: N/N passed」。

#### 2. 覆蓋既有檔前必須 git show HEAD

`Write` 是破壞性操作。對既有檔一律 `Read` + `StrReplace`。

**預防**：見 `.cursor/rules/006-verification.mdc` 新增的「改檔前 checklist」。

#### 3. vitest alias 順序是 Vite 8.x 行為

陣列形式 `resolve.alias` 按宣告順序匹配 prefix。Specific first, generic last。

**預防**：見 `.cursor/rules/016-config-and-tsconfig-discipline.mdc` 新增的 vitest alias 順序範例。

#### 4. CI 配置變更必須「7 surfaces 一致」

`.gitignore` + `package-lock.json` + `*.github/workflows/*.yml` + `tsconfig*.json` `include` + `vite.config.ts` alias + `vitest.config.ts` alias + `tsconfig.app.json` `paths` — 這 7 個地方任一不一致就讓 CI 與 IDE 行為分裂。

**預防**：見 `.cursor/rules/016-config-and-tsconfig-discipline.mdc` 新增的 7 surfaces 表。
